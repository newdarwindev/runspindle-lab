# Implementation plan and honest scope

Implemented here: two pinned Git submodules, exact gitlink checks, an offline report generator, fail-closed tier selection, synthetic harness tests and a manual local CI entrypoint. The demo suite is not edited or made dependent on upstream code.

Next gates, in order:
1. Provision/qualify the owner's isolated Strix and MacBook Pro lanes. Repository admission, host identity and prerequisites must be verified from actual jobs.
2. Add bakery adapter over explicit Runspindle contracts. Observe persisted business results independently. Record success, interruption, replay, wrong-scope and uncertain-effect behavior. Preserve immutable accepted bytes and source pins.
3. Add bookkeeper recovery with explicit sign-in handoff and fresh account verification. Never turn unresolved outcomes into success or retry external effects blindly.
4. Exercise real component and product lanes with synthetic offline data. Keep scripted peers and unimplemented native/Tether seams explicit; existing upstream H02/H07 evidence is not automatically evidence for these cases.
5. Produce screenshots, recordings, rich comparative reports and versioned media with hashes and provenance. Review public content before Pages publication.
6. Establish stable measurements before baseline guidance or optimization claims. Record failed and blocked runs, quality, operator interventions, runtime, model/tool usage when genuinely measured, and environment identities. No invented savings.

The product and component adapters intentionally return blocked today. Fixture contract tests are a separate command and can never satisfy product acceptance.
